# TaskEase 需求

## 产品与平台

TaskEase，中文显示名为轻程，是 Apple Silicon Mac 上的原生菜单栏应用。目标系统为 macOS 14 及以上，使用 Xcode 27、Swift 6、SwiftUI、AppKit 和 Observation。

用户从菜单栏查看占用，为指定应用配置后台限制。后台指失去系统前台焦点或应用隐藏。仅窗口最小化而仍保留前台焦点不视为后台。离开前台后等待指定时间，再执行规则；回到前台恢复。

## 规则流程

1. 从“运行中的应用”中选择应用。
2. 打开“限制后台资源”，设置生效时机和 CPU 使用上限。
3. 打开顶部“启用限制”总开关。
4. 应用进入后台，等待结束后执行规则。
5. 切回应用，确认限制解除。

默认行为为“保持原样”。无有效规则时总开关关闭并置灰，点击后提示用户先设置应用规则。关闭总开关暂停执行并保留配置。已保存规则列表包含正在运行和未运行的应用；关闭某条规则保留其配置，移除规则删除该记录。

现有 rules.v1 配置继续按 bundle identifier 匹配。模式的持久化原始值保持稳定，显示名称独立调整。

## 指标

应用 CPU 使用率由累计 CPU 时间差计算，单核满载为 100%。同一应用的自有辅助进程合并显示。物理内存采用 footprint；磁盘读写和中断唤醒采用累计计数差分。

整机 CPU 来自 host 计数，以全部核心的总能力计算。整机 GPU 是设备驱动利用率估计值；应用 GPU 由各 GPU 客户端的累计执行时间差分得到，只用于显示和排序。热状态提供正常、轻度升温、较高、严重四级状态。无法读取的指标显示不可用。

## 网络监控与配置

网络实验功能默认关闭，开启后应用列表和详情提供接收、发送速度，进程信息中显示各个成员的速度。设置可关闭网络显示。数据来源为系统进程计数，第一帧及失效基线显示不可用。网络读取跟随数据面板启停。

网络规则独立保存，包含联网模式、作用时间、等待时间与上下行上限。已配置列表包含 CPU 与网络规则。当前构建支持监控与配置，执行状态为测试功能尚未实现；签名与系统批准完成后再验证实际阻断和限速。详细设计见 [网络文档](Networking.md)。

## 控制规则

| 行为 | 执行方式 |
| --- | --- |
| 保持原样 | 观察占用，解除 TaskEase 施加的状态 |
| 性能限制 · CPU 上限 | 应用自有进程共享平均 CPU 上限，超额时暂停并在额度恢复后继续 |
| 性能限制 · 暂停 | CPU 上限滑杆最左端；生效期间全部自有进程保持暂停，回到前台或移除规则时恢复；不能设为始终限制 |
| 后台音量 | 0%（静音）至 90%。用 Core Audio 进程截取（macOS 14.2+）静音应用原声；非静音档位经私有聚合设备按增益（音量百分比的平方）转播到默认输出设备。截取与聚合设备随本应用退出由系统销毁 |
| 降低优先级 | 启用 Darwin 背景调度，前台解除本工具的请求，没有固定 CPU 上限；暂停时不使用 |

三项在“限制后台资源”打开后按同一生效时机执行，可任意组合。优先级分档已实测排除：调高 nice 值后普通权限无法改回；Darwin 角色中间档、taskpolicy 的吞吐与延迟分级在满载竞争下与默认档 CPU 时间相同。因此优先级只提供可完整撤销的后台调度一档。旧版单一模式规则读取时迁移，保存时同时写入旧 `mode` 字段供降级读取。

CPU 上限范围为单核的 5% 至 200%，默认 20%。生效时机使用预设档位：始终限制（暂停应用除外），或离开前台后 1、3、5、10、30 秒及 1、2、5 分钟，默认 3 秒。始终限制保存为独立字段，旧规则保持后台限制含义。在应用已经位于后台时开启总开关，会重新开始等待时间。

限制作用于整个受控进程，可能影响声音、网络心跳和任务完成时间。精确 FPS 上限、独立 GPU 百分比配额、网络限速和传感器摄氏度读数需要单独验证。

## 节省报告

节省报告估算规则生效期间省下的资源，从管理窗口页眉、菜单栏面板或应用菜单（⌘2）打开。显示今天和最近 7 天省下的 CPU 时间、每天的柱状图和按应用排行，并在界面写明估算口径。不额外采样，只使用显示刷新与 2 秒控制检查已有的读数。

- 基线：应用在后台且未受性能限制（含等待期、只调音量、总开关关闭）时的平均 CPU，按观察时长加权，近似最近约 10 分钟；GPU 基线含画面合成归因，只来自显示采样。观察不足 20 秒或 14 天未更新的基线不使用。
- CPU 节省：max(0, 基线 − 实测) × 受限时长，单核口径；只统计 CPU 上限与暂停，降低优先级和后台音量不计入。
- GPU 节省：仅暂停期间按 max(0, 基线 − 实测) × 时长计入，暂停的进程不提交 GPU 工作；CPU 上限期间控制检查不读取 GPU，不估算。
- 相邻读数间隔超过 12 秒（睡眠、停止采样）不计入；睡眠后重建时间基准。
- 不估算电量与温度。
- 记录按本地日期保存 30 天，写入本地数据目录，随“清除数据并退出”删除；可在报告中单独清除。

## 智能建议

管理窗口在系统概览下方显示建议提示条：还没有规则的运行中应用，在后台未受限时的平均 CPU 或 GPU（含画面合成归因）超过阈值，即列为“建议限制”。基线与节省报告共用，需要至少一分钟的后台观察，因此首次打开管理窗口约一分钟后出现。系统应用、不可控制的应用和已有 CPU 或网络规则的应用不列出。

- 阈值默认 CPU 10%（单核）、GPU 5%，可在建议列表中调整。
- 推荐方式按应用类型：音乐、播客类与聊天、邮件类降低优先级（暂停会中断播放或收不到通知），类型取自应用包声明的类别并以名称关键词补充；持续显示画面（平均画面合成 ≥ 1% 或 GPU 超过阈值）的暂停；其余限制 CPU 到 20%。生效时机均为离开前台 3 秒。
- “套用”一键保存为规则；此前没有任何有效规则时同时打开总开关，用户主动关闭的总开关保持关闭。
- “忽略”的应用不再建议，可在列表底部恢复。关掉提示条后，只有出现新的建议才再次显示。
- 建议设置保存在偏好域的 suggestions.v1。

## 临时操作与自动化

菜单栏面板中占用最高的五个应用（以及正在临时暂停或暂不限制的应用）右侧提供临时操作：

- 临时暂停 15 分钟、1 小时或 4 小时：应用在后台时暂停，不等待；切回前台照常使用，再次离开立即暂停，直到期限。与规则和总开关无关，系统应用与不可控制的应用不提供。
- 立即恢复：结束临时暂停；规则正在限制时，规则暂停执行 1 小时或直到下次切回该应用。
- 恢复按规则限制：提前结束“立即恢复”。

临时操作只保存在内存中。暂停与暂停规则一样交给工作进程执行、写入恢复记录；轻程退出、睡眠、控制进程失联或主应用崩溃时按现有恢复机制解除，应用退出后临时操作失效，重新打开不会沿用。

规则模板：设置的“自动化”分组提供导入、导出。文件为 rules.v1 相同格式的 JSON（bundle identifier 到规则，含旧版 `mode` 字段），旧版本导出的规则可直接导入。导入替换同一应用的规则、保留其他规则，不改变总开关；系统应用、本应用与无效标识跳过，最多 500 条、1 MB。

快捷指令提供“设置后台限制”（打开、关闭、切换）、“临时暂停应用”（1–240 分钟）和“恢复应用”。URL Scheme 提供同样的操作：`taskease://enable`、`disable`、`toggle`、`pause?app=<bundle id>&minutes=60`、`resume?app=<bundle id>`。没有有效规则时不能打开总开关；无效或失败的链接只发出提示音。

## 应用筛选与权限

默认隐藏 Apple 系统应用，用户可在列表或设置中开启显示。自有辅助进程并入所属应用；独立系统服务和其他用户进程不加入应用控制组。

控制前验证当前用户、PID、启动时间、可执行路径和所属应用。TaskEase 自身、Apple 系统应用、共享系统服务以及已经被外部暂停的进程不接管。不解除已有的外部后台调度状态。

## 设置与窗口

当前用户按单实例运行。重复启动恢复已有管理窗口。菜单栏资源采用 18 点逻辑尺寸及 Retina 图片。管理、设置、帮助、关于和许可证窗口复用已有实例；有打开或最小化的应用窗口时保留 Dock 入口，关闭全部窗口后继续菜单栏运行。设置提供“在菜单栏显示图标”，默认开启；关闭或按住 ⌘ 把图标拖出菜单栏后不再显示图标，后台规则照常执行，关闭全部窗口后没有 Dock 入口，从启动台、Spotlight 或再次启动应用恢复管理窗口。

项目采用 GPL-3.0-only。源码与应用包均包含完整许可证，关于信息提供版权、许可和无担保说明，以及许可证查看入口。

显示设置提供跟随系统、浅色、深色，以及 1、2、5、10 秒数据刷新间隔。刷新间隔只影响可见数据面板。管理窗口默认仅在前台刷新，可在设置中关闭该选项；关闭后管理窗口开着（含遮挡与最小化）即持续刷新，关闭窗口后停止。详情折线图随排序依据显示最近 3 分钟的记录，横轴只计记录时间，暂停期间的空档不占位置；后台时受控应用借控制检查继续记录 CPU、内存和磁盘。切回前台立即更新，菜单栏面板打开时刷新。控制心跳与等待期限独立调度。

## 数据管理

设置提供“清除数据并退出…”入口。用户确认后恢复受控进程、停止采样、删除本应用配置和本地数据，再退出应用。清理范围限定为本应用偏好域与明确归属的目录。失败向用户报告并允许重试。

## 使用统计

关于窗口提供匿名使用统计开关，新安装默认开启，已有用户选择继续保留。开启后通过 PostHog Capture API 上报随机安装标识、基础环境及本应用功能配置概况，关闭用户资料与 IP 地区补充。启动时立即检查，持续运行每 6 小时及跨日时发送；重启、唤醒和联网恢复遵循相同去重期限。退出、睡眠和关闭开关时停止任务，失败重试有间隔与窗口次数上限。统计与应用监控、资源控制相互独立。详细字段与维护流程见 [PostHog 文档](PostHog.md)。

## 性能目标

采样在独立 actor 上执行。完全遮挡、最小化或关闭数据窗口时停止显示采样；后台规则仍按需检查。没有可见数据面板和需要执行的规则时，不保留周期采样定时器，也不启动控制进程。

macOS 26 起采用类型化工作区通知，macOS 27 起采用类型化窗口可见性消息。较早系统使用公开通知执行相同流程。性能目标需用 CPU、物理内存和唤醒次数验证；实际续航与温度变化按应用另行对比。

## 验收条件

- 主开关在无有效规则时置灰；删除最后一条有效规则后关闭。
- 运行列表默认隐藏系统应用，显示开关不赋予系统进程控制权限。
- 已配置规则在应用退出后保留，支持离线编辑与移除。
- 前台切换、隐藏、等待、全局暂停和正常退出保持控制状态正确。
- 慢速显示刷新不推迟控制心跳或后台等待期限。
- 控制器失联、退出、强制结束以及重启后的恢复经过测试。
- 设置、帮助、关于、许可证窗口及 Dock 入口生命周期经过交互验证。
- 自动测试使用独立数据与自建负载进程。
- 节省估算的基线、差值、日期切分、间隔上限与持久化经过测试。
- 建议的阈值、观察时长、推荐方式、忽略与一键套用经过测试。
- 临时暂停与立即恢复的状态、应用退出与关闭时的结束、链接解析、模板导入导出与命令结果经过测试。
