# TaskEase 首版需求

## 目标

用户从菜单栏查看应用占用，选择某个应用的后台规则。后台指失去系统前台焦点或应用隐藏。仅窗口最小化而仍保留前台焦点不视为后台。应用进入后台后等待指定时间，再降低调度优先级或限制平均 CPU。回到前台时解除由 TaskEase 施加的限制。

产品名为 TaskEase，中文显示名为轻程。首版面向 macOS 14 及以上，使用 SwiftUI 和 AppKit。

## 使用流程

1. 打开菜单栏面板，查看整机状态和当前高占用应用。
2. 打开应用管理窗口，搜索并选择一个应用。
3. 选择温和调度或 CPU 预算，设置后台等待时间。
4. 切换到其他应用，等待后观察状态和 CPU 变化。
5. 切回该应用，确认限制已解除。

新应用默认不管理。已有规则在应用重启后按 bundle identifier 重新匹配。规则配置独立保存于 TaskEase 的用户域。

## 指标

应用 CPU 使用率由累计 CPU 时间差计算，单核满载为 100%。内存采用物理 footprint。磁盘指标显示累计计数差分。应用分组只包括当前用户、应用 bundle 内的可执行文件和主进程。

整机 CPU 来自 host 计数。GPU 是设备驱动利用率估计值，不归属某个应用。热状态使用 ProcessInfo 的正常、轻度升温、较高、严重四级状态。

## 控制模式

| 模式 | 行为 |
| --- | --- |
| 不管理 | 显示占用，解除本工具施加的状态 |
| 温和调度 | 后台启用 Darwin 背景调度，前台解除本工具的请求 |
| CPU 预算 | 将应用自有进程的 CPU 使用合计纳入同一预算，以暂停和恢复实现平均额度 |

CPU 预算范围为单核的 5% 至 200%，默认 20%。后台等待范围为 0 至 30 秒，默认 3 秒。限制影响整个受控进程，包括其网络、音频和心跳。用户必须自行选择适用应用。

## 边界

首版不提供任意第三方应用的精确 FPS 上限、GPU 百分比上限或网络限速。应用专用的视频接口适配另行验证。

不控制 TaskEase 自身、其他用户的进程、Apple 系统应用、系统共享服务、已被其他方式暂停的进程。不解除已有的非本工具后台状态。

## 应用外围

正常应用按当前用户单实例运行，重复启动恢复已有管理窗口。菜单栏图标使用 18 点逻辑尺寸，并提供 Retina 图片。管理窗口打开或最小化时保留 Dock 入口，关闭窗口后继续菜单栏管理；菜单栏面板提供再次打开与退出入口。

本机应用包采用 Release 配置。开发预览与测试数据使用独立环境，正常应用按用户保存的规则运行。

## 验收条件

- 菜单栏面板和应用管理窗口显示真实采样数据，缺失指标有明确状态。
- 规则在切屏、隐藏、快速来回切换和应用重启时保持正确。
- CPU 预算按应用分组合计，显示值与单核口径一致。
- 前台、全局暂停和正常退出解除由本工具施加的控制。
- 主应用失联、控制进程退出、控制进程被强制结束和重启后的恢复经过实际测试。
- 无规则时不启动控制进程。采样与控制开销需要在本机测量并记录。
- 自动测试只控制自建测试进程；真实应用首次运行默认不管理。
