# TaskEase 验证

## 实际环境

2026-10-10，M5 MacBook Air，24 GB，macOS 27.0.1，Xcode 27.0。声明的最低部署版本是 macOS 14，尚未在 macOS 14 或 Intel Mac 上实机验证。

## 已完成检查

- Xcode 原生构建成功，无编译错误。
- Swift Testing 9 项通过，覆盖前台恢复、后台等待、快速返回、只读应用、PID 重用、预算超额、额度上界及配置解码。
- XCTest 界面测试 2 项通过，覆盖管理窗口、搜索、系统应用只读状态、全局管理开关。
- 总计 11 项测试全部通过，最终记录为 2026-10-10 10:19 的运行。
- SwiftUI 管理窗口和菜单面板完成渲染检查。
- 真实只读快照读到 44 个应用，43 个有可读进程数据，10 个包含多个自有进程。

## 进程控制自检

对项目 build/TaskEase.app 运行最终自检通过。自检仅启动自身创建的限时负载进程，不限制已有应用。每个负载进程 20 秒后自动结束，并在测试清理阶段提前结束。复制后的应用通过 codesign --verify --deep --strict 验证。

| 检查 | 实际结果 |
| --- | --- |
| 未限制单进程 | 99.61% 单核 CPU |
| 单进程 20% 预算 | 21.06% |
| 解除预算 | 100.07% |
| 两进程合计 20% 预算 | 20.15% |
| 温和调度与解除 | 通过，任务优先级 31 → 4 → 31 |
| 主控制器失联 3 秒 | 恢复通过 |
| 强制结束控制进程 | 主应用补偿恢复通过 |
| 两进程同时解除 | 通过 |

CPU 预算存在短时超额和调度误差，不能保证瞬时精确比例。

## 工具自身开销

最终启动的 Debug 构建在菜单关闭、无应用规则时，18 秒片段测得约 0.55% 单核 CPU，物理 footprint 约 16.4 MiB。默认没有控制子进程。

初始固定 2 秒后台采样约 2.92% 单核 CPU。改为无界面、无启用规则时 8 秒采样后，开销降低。该片段不是电池续航或瓦数测量，不能据此给出节能百分比。

## 已知边界

- GPU 数据是未承诺稳定的驱动字段。字段缺失时显示不可用，不做按应用归因。
- 不提供通用精确 FPS、GPU 配额或网络限速。
- 只管理当前用户、应用 bundle 内的已验证进程；不能控制 root 或系统共享服务。
- 另一个进程限制器同时管理同一目标，可能使暂停归属无法区分。
- 真实应用的音频、远控连接、下载及任务完成时间需按具体应用另行对比。

## 复跑

在 Xcode 中运行 TaskEase 的测试计划。进程自检使用 Scripts/run-self-check.sh，并传入 Xcode 构建的应用可执行文件。只读快照使用该文件的 --snapshot 参数。

测试和采样结果摘要保存在 `Artifacts/`。摘要保留检查结果和采样条件，省略本机 PID 与临时绝对路径；原始本机记录保存在不纳入 Git 的 `Artifacts/local/`。
