## 空闲开销

版本 1.1.0 的 Release 实例在许可界面更新前完成了 25 秒只读测量：

| 指标 | 结果 |
| --- | --- |
| CPU，单核口径 | 约 0.0014% |
| 物理 footprint | 约 35.1 MiB |
| 使处理器封装离开空闲状态的唤醒 | 0.12 次/秒 |
| 中断唤醒 | 0.32 次/秒 |

测量时窗口不可见、没有启用规则、没有控制进程，Mac 桌面锁定。结果表示这一条件下的空闲开销；可见数据窗口、执行限制和不同应用负载需要分别测量。不能据此推算实际续航或温度降低幅度。

记录见 `Artifacts/overhead.json`。采样在独立 actor 上执行；没有显示或执行需求时停止周期定时器。显示与控制使用独立计数基线，控制检查不替换尚未到期的显示数据。

## 管理窗口在后台的开销

2026-10-11，对重新启动的最终 Release 包测量 25 秒。管理窗口已打开，应用未隐藏且位于后台，前台刷新选项开启，显示间隔为 1 秒，没有启用规则或控制进程。平均 CPU 为单核的 0.0084%，物理 footprint 为 36.3 MiB，中断唤醒 0.44 次/秒。

该记录在启动后不久取得，内存不代表长时间使用后的占用。记录见 `Artifacts/foreground-refresh.json`。

## 网络监控开销

2026-10-11，Release 主窗口在前台、网络监控开启、2 秒刷新且没有执行控制规则时，25 秒采样得到主进程 CPU 1.95%、已退出读取子进程 CPU 0.52%，合计约单核的 2.47%。主进程物理 footprint 约 51.5 MiB。

窗口保持打开但应用位于后台时，主进程与子进程合计 CPU 约 0.0137%，读取子进程 CPU 为 0，中断唤醒 0.52 次/秒。两种条件的记录见 `Artifacts/network-overhead.json`。这些结果只代表本机对应采样条件，不是长期平均或电池续航结果。

## 使用边界

- GPU 为整机驱动估计值；热状态采用系统等级。
- 控制对象为当前用户、应用 bundle 内的已验证进程。
- 同一目标由一个进程限制器管理，保持暂停归属明确。
- 真实应用的音频、远控心跳、下载和任务完成时间需按应用验证。
- 精确 FPS、独立 GPU 配额、网络限速和传感器摄氏度读数是后续研究内容。

## 复跑

解锁 Mac、回到桌面并退出正常运行的轻程副本后，在 Xcode 按 Command-U 运行测试。在项目根目录执行：

```sh
sh Scripts/build-app.sh
python3 Scripts/check-application.py build/TaskEase.app
sh Scripts/run-self-check.sh "$PWD/build/TaskEase.app/Contents/MacOS/TaskEase"
python3 Scripts/measure-overhead.py PID --seconds 25
```

PID 使用当前 TaskEase 实例的进程号。测量前记录窗口可见性和规则状态。完整本机临时记录保存在 Git 忽略的 `Artifacts/local/` 中。
