# 界面评审与改进

产品定位：你没在看的应用，就让它歇着。界面的主要任务只有一条：选应用 → 打开限制 → 选时机和方式；其余信息（占用、图表、磁盘、进程）用来帮助判断。

本轮评审基于 1.5.2 的管理窗口、规则编辑、菜单栏面板、设置、帮助与关于，以及 `Scripts/render-previews.sh` 的示例渲染。改前改后的渲染图保存在 [Artifacts/ui-refresh](../Artifacts/ui-refresh)。

| # | 问题 | 影响 | 改进 | 状态 |

## 其他检查

- 信息密度：系统概览单行、列表两行、详情卡片分组，密度合适；改动只调整顺序与强调，没有新增常驻面板。
- 空状态：没有规则时“已配置规则”列表有说明和“选择应用”按钮；未运行应用的规则说明放到标题下方。
- 深浅色：卡片使用 `primary` 透明度与语义色，状态色使用系统色，深浅色都能区分；角标描边使用窗口背景色，两种外观下都与图标分开。
- 原生控件：开关、滑杆、分段控件、菜单、右键菜单和 `ContentUnavailableView` 都是系统控件，没有新增自绘装饰。
- 数据与行为：`rules.v1` 格式、规则校验、Policy 状态计算和进程控制路径都没有改动；新界面只调用已有的 `setRule`、`setEnabled`、`resetRule`。

## 与节省报告分支合并

`claude/blissful-rosalind-331017` 在现有视图中只插入了几行：

- `ContentView` 页眉的 `SavingsBadge` 与分栏前的 `SuggestionBanner`：页眉和 `HSplitView` 位置未变，可原样插入。
- `MenuPanel`：本轮把行抽成 `MenuAppRow`。合并时把 `QuickActions(model:app:)` 放进 `MenuAppRow` 的 `HStack` 末尾（数值之前或之后），`ForEach` 的数据源改成 `QuickActions.rows(...)` 即可。
- `StatusLabel` 的颜色：本轮把 `tint` 改成静态函数 `StatusLabel.tint(_:)` 并新增 `symbol(_:)`；`.held`、`.released` 需要在两个 switch 里各加一行。
