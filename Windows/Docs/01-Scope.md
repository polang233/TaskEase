# 01 范围与能力对照

## 产品定义

轻程 Windows 版常驻在任务栏通知区域（托盘）。用户可以在这里看到每个应用占用了多少资源，也可以给单个应用设置规则：应用离开前台一段时间后，自动限制 CPU、降低优先级、暂停应用、限制帧率或限制网络，切回前台立即恢复。

用户可见的行为与 macOS 版保持一致：规则流程、默认值、取值范围、主开关、离线编辑、“清除数据并退出”都相同，见 [../../Docs/Requirements.md](../../Docs/Requirements.md)。本文只列出 Windows 上不同或新增的部分。

**“后台”的定义**：应用的窗口都不是前台窗口，就算后台。最小化的窗口通常会同时失去前台。系统托盘里没有窗口的进程，按“一直在后台”处理。

## 能力等级

| 标记 | 含义 |
| --- | --- |
| A | 完整实现，不需要管理员权限 |
| A+ | 完整实现，而且效果好于 macOS 版 |
| B | 需要安装可选服务（一次 UAC 授权） |
| C | 部分实现，或使用近似口径，界面上要如实标注 |
| X | 不做 |

## 不做的事（首版）

- CPU 温度、风扇控制，以及任何写入硬件的操作。
- 控制其他用户的进程、系统服务、受保护进程（PPL）、以管理员身份运行的进程（核心不提权运行）。
- 对带反作弊的游戏启用注入。已知的反作弊模块列入拒绝名单，见 06。
- Windows 10 专门适配、ARM64（首版）。
- 微软商店上架（MSIX 要求签名，并且限制较多）。

## 拒绝控制的进程（与 macOS 的“系统应用”对应）

满足以下任一条件的进程只显示，不允许设置规则：

- 位于 `%WINDIR%` 下（如 explorer.exe、dwm.exe、csrss.exe、audiodg.exe、svchost.exe、ApplicationFrameHost.exe、TextInputHost.exe）。
- 会话 0 中的进程，或属于其他用户 SID 的进程。
- 令牌已提权，而核心没有提权；或进程是受保护进程。
- TaskEase 自己的进程，以及输入法进程（名单在 te-sys 中维护）。

列表默认隐藏 `%WINDIR%` 下的应用，设置中可以打开显示，但打开显示不会让它们变得可以控制，与 macOS 一致。

## 性能目标

以下数值是验收目标，需要在实机上测量并记录芯片型号、系统版本、窗口状态和规则状态（09 测试）：

| 场景 | 目标 |
| --- | --- |
| 核心常驻、没有规则、没有界面 | 没有周期定时器；私有工作集 ≤ 10 MB；10 分钟平均 CPU 接近 0 |
| 核心常驻、5 条规则生效、没有界面 | 每 2 秒控制检查一次；10 分钟平均 CPU ≤ 单核的 0.2% |
| 管理窗口打开，1 秒刷新，约 300 个进程 | 核心加界面进程合计 CPU ≤ 单核的 3%；内存上限由 D-04 的评测确定 |
| 界面关闭后 | 界面进程在 2 分钟内退出（D-02），之后回到常驻水平 |
